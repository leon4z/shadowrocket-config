# Shadowrocket Config

基于 [johnshall 懒人配置](https://github.com/johnshall/Shadowrocket-ADBlock-Rules-Forever) 的 Shadowrocket 分流配置，提供手动选择、自动故障切换和混合分流三种通用模式，支持按服务和地区选择出口。

本仓库提供分流规则与策略组，不提供代理节点。使用前，请先在 Shadowrocket 中添加自己的节点或节点订阅。

## 选择配置

| 模式 | 普通代理流量 | AI / Google 服务 | 配置文件 |
| --- | --- | --- | --- |
| 手动选择 | 默认跟随首页选择，可按服务另选分组 | 默认跟随首页选择，可另选分组 | `Shadowrocket-select.conf` |
| 自动切换 | 使用「速度」组自动故障切换 | 使用「稳定」组自动故障切换 | `Shadowrocket-fallback.conf` |
| 混合分流 | 默认跟随首页选择，可按服务另选分组 | 使用「稳定」组自动故障切换 | `Shadowrocket-hybrid.conf` |

三种模式都保留上游的国内直连规则与服务分类。表中描述的是代理流量；原本默认直连的服务不会因此全部改走代理。

手动版不包含「速度」「稳定」组；自动版保留两组；混合版仅保留「稳定」组。**三种模式的地区组都保持 `url-test` 自动测速**：手动选择某个地区组后，由该组自动选择节点。

**先选一份即可。** 三份可以同时导入，但同一时刻只启用一份，不会叠加生效。每份配置的分组成员需要分别设置；在自动版中填好的稳定节点，不会自动复制到混合版。

**自动版和混合版必须先设置「稳定」组。该组默认没有节点，导入后不能直接使用 AI / Google 分流。** 手动版没有这个组。

## 1. 导入配置

以下使用 Shadowrocket 中文界面的名称，不同版本的图标位置可能略有差异。整个设置过程都可在 App 内完成，无需编辑配置代码。

1. 确认「首页」已有自己的节点。若还没有，可通过首页右上角「+」添加；节点订阅选择类型「Subscribe」，填入自己的订阅 URL 后保存。
2. 从上方对应的代码块中复制配置的完整地址，也可使用代码块右上角的复制按钮。
3. 打开底部「配置」页 → 右上角「+」→ 在 URL 栏粘贴链接 → 点「下载」。
4. 下载完成后，配置文件出现在列表中。先按下面对应模式完成设置，再启用它。

**两个入口不要混淆：** 点配置文件名称，会出现「使用配置」等操作；点文件右侧的 **ⓘ**，进入编辑页面。进入「代理分组」后，点分组名称是查看成员或选择出口，点分组右侧的 **ⓘ** 才是编辑类型和成员。

## 2. 按所选模式设置

### 手动版：在首页选节点

1. 在「首页」展开节点所在的订阅，点选想使用的节点，确认它被选中。
2. 保持服务分组的默认选择即可。AI、谷歌服务、YouTube 等需要代理的服务默认选择 **PROXY**，意思是跟随首页当前选中的节点。
3. 按第 3 节启用配置。以后想换出口，直接回首页选择另一个节点。

若某个服务组之前被改选为地区组，它就不再跟随首页。到「配置」→ 该文件右侧 **ⓘ** →「代理分组」→ 点该服务的名称 → 重新选择 **PROXY**。原本选择 DIRECT 的服务可以保持直连。

### 自动版：填好稳定组，检查速度组

1. 先按下面的「保留本地修改」处理，再设置自己的分组成员。
2. 按「给稳定组添加节点」加入自己选定的稳定节点。
3. 打开待使用配置的「代理分组」，点「速度」，确认它列出了可用节点。默认会根据节点名称中的地区关键词匹配；有合适节点时无需修改。
4. 若速度组为空，或只想使用自己挑选的一批节点，按稳定组的同样方法编辑「速度」：保留类型 **fallback**，关闭「订阅」，清空「正则」，逐个添加具体节点并排序后保存。
5. 保持 AI、谷歌服务选择「稳定」，其他需要代理的服务选择「速度」，再按第 3 节启用配置。此时在首页换节点，不会改变这些服务的出口。

### 混合版：稳定组负责 AI / Google，首页控制普通代理流量

1. 先按「保留本地修改」处理，再按「给稳定组添加节点」设置稳定节点。
2. 在「首页」选择希望普通代理流量使用的节点。
3. 保持 AI、谷歌服务选择「稳定」，其他需要代理的服务选择 **PROXY**，再按第 3 节启用配置。
4. 日常只需在首页切换普通节点，AI / Google 仍由稳定组负责故障切换。

### 保留本地修改

当前发布的三份通用配置已移除 `update-url`，引用的远程规则集地址保留。**但 Shadowrocket 通过 URL 导入时可能自动补回下载地址，不能仅凭远程文件没有该字段就认为本地修改不会被覆盖。** 需要自定义分组成员时，新旧版本都按以下步骤处理。已自定义的配置不要直接通过「更新配置」迁移，以免该次更新覆盖已有成员。

1. 在「配置」页点原文件右侧 **ⓘ** →「复制」。返回列表，找到新增的副本；点副本名称 →「重新命名」，可改为便于识别的名称，例如「我的混合分流」。后续编辑和启用都选择这份副本。
2. 打开底部「设置」→「更新」一栏中的「配置」→ 关闭「自动后台更新」。**这是所有配置共用的开关**，会停止这项后台任务对其他配置及其引用资源的自动更新；节点订阅的更新设置是独立的。
3. 后续不要对已自定义的副本执行「更新配置」。这可能用远程版本覆盖你添加的节点成员。

**仅复制、改名不足以防止覆盖。** 自定义副本按上述方式手动维护：要刷新它引用的远程规则集，可点文件名称 →「使用配置」，或点右侧 **ⓘ** →「编译配置」。这样刷新规则资源，不用重新下载整份配置。仓库未来调整分组结构时，需要另行导入新版并重新设置成员。更新操作的区别可参考 [Shadowrocket 社区使用手册](https://github.com/LOWERTOP/Shadowrocket/wiki)。

### 给稳定组添加节点

稳定组由你指定候选节点，App 在这些节点之间自动故障切换。至少添加 1 个；希望有备用线路，可添加 2–3 个自己确认可用、适合目标服务的节点。

1. **复制节点完整名称。** 打开「首页」→ 展开节点所在订阅 → 点节点右侧 **ⓘ** → 找到「备注」，在文字栏中全选并复制，然后返回。不要修改节点的服务器或认证信息。
2. **打开稳定组编辑页。**「配置」→ 待使用的配置或副本右侧 **ⓘ** →「代理分组」→「稳定」右侧 **ⓘ**。
3. **切换为手动填写成员。** 保持「类型」为 **fallback**，保持「订阅」关闭，清空「正则」栏中原有的 `(?!)`。先不要保存空组。
4. **加入节点。** 在下方「策略」区域的「添加」输入框中粘贴刚复制的完整备注，点该行左侧的 **+（插入）**。确认它变成列表中的一行。只把文字留在输入框中，不等于已经加入。
5. **保存后继续添加。** 点右上角「保存」。要加入下一个节点，回首页复制它的备注，再返回稳定组编辑页添加并保存。全部加入后，用成员右侧的拖动手柄排序，把优先使用的节点放在上面，备用节点放在下面，再次保存。
6. **检查结果。** 返回分组列表，点「稳定」名称，确认刚添加的节点都在组内；再按第 3 节检查实际使用结果。

这里粘贴的是**节点备注**，不是节点订阅链接，也不是服务器地址。名称需要完整一致，包括旗帜、空格和符号；避免节点重名，订阅更新后若名称变化，也要同步更新组内成员。稳定组中添加具体节点即可，不要填 PROXY、DIRECT 或其他自动分组。

### 可选：让某个服务使用地区组

例如只想让 YouTube 走日本：在「配置」→ 当前文件右侧 **ⓘ** →「代理分组」中，点 **YouTube 的名称** → 选择「日本节点」。此后该服务使用日本组内自动选择的节点，其他服务保持原来的选择。

地区组包括香港、台湾、日本、新加坡、韩国和美国，按节点名称中的地区关键词或旗帜匹配。先点地区组名称检查它是否有成员；空组不要选。地区名称只用于筛选，不能保证流媒体或其他服务可用。自动版、混合版的 AI / 谷歌服务只提供「稳定」选项。

## 3. 启用并验证

1. 回到「配置」列表，点准备好的文件名称 →「使用配置」，等待规则加载完成。确认文件旁出现**复选标记**；圆点表示默认配置，不等于当前正在使用。
2. 回到「首页」→「全局路由」→ 选择**配置**，然后开启连接。不要选成「代理」，否则不会按这份配置分流。
3. 到该文件的「代理分组」检查：手动版需要代理的服务选 PROXY；自动版的 AI / 谷歌选稳定、其他代理服务选速度；混合版的 AI / 谷歌选稳定、其他代理服务选 PROXY。保留默认 DIRECT 的服务不在此列。
4. 点文件右侧 **ⓘ** →「测试规则」，在 Host 栏输入实际要访问的域名，例如 `www.google.com`、`www.youtube.com`，查看命中的规则和策略是否符合所选模式。
5. 最后用浏览器或目标 App 实际访问一次。规则测试能说明分流去向，不能证明节点能访问目标服务。

如果导入了多份配置，切换模式时要重新「使用配置」，并检查新启用的那份是否已经设置好成员。

## 常见问题

| 现象 | 在 App 中检查什么 |
| --- | --- |
| 导入后 AI / Google 不通 | 自动版、混合版的稳定组是否仍为空；是否点了「+」加入成员并保存；节点本身能否访问该服务 |
| 首页换了节点，某个服务没变 | 自动版由分组控制；混合版的 AI / Google 也由稳定组控制。手动版若要跟随首页，该服务组应选择 PROXY |
| 地区组或速度组没有节点 | 节点名称可能不匹配默认筛选条件；可在该组编辑页中清空正则、手动添加成员。地区组保留 url-test 类型，速度组保留 fallback 类型 |
| 配好了，过几天成员又没了 | 检查是否触发了整份配置更新或重新导入；URL 导入可能补回更新地址，防覆盖步骤见上文 |
| 另一份配置里找不到刚添加的节点 | 成员设置属于各自的配置，需要分别编辑；切换后也要确认启用了正确的文件 |

## 更新与使用限制

- 每天北京时间 07:00 从上游重新构建并校验，通过后更新 `release` 分支中的配置；校验失败时保留上一版。
- 通用版发布文件不含 `update-url`，但 URL 导入可能补回更新地址；保留个人修改请按上文操作。「使用配置／编译配置」仍可更新所引用的远程规则集。分组结构等主文件变更需主动迁移，CDN 与客户端缓存可能导致更新延迟，更新时间变化不保证已拿到新内容。
- 配置更新与节点订阅更新相互独立；导入配置不会添加节点。
- 「速度」「稳定」都是 **fallback**：依据测试结果，按成员顺序选择可用节点，不保证选中延迟最低的节点。默认正则筛选出的速度组成员顺序取决于客户端节点列表；手动添加时可拖动排序。
- 地区组是 **url-test**：按延迟测试自动选择，使用 100 毫秒切换公差，减少小幅延迟波动造成的频繁切换。
- 自动测试周期为 600 秒、超时为 5 秒。两次测试之间节点可能失效，故障切换不保证即时发生；测试成功也不保证所有网站、地区限制服务或长连接可用。
